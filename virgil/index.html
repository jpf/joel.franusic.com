1. Virgil

Virgil is a tool that guides you, step-by-step, through creating a fully functional 9P file server.

Writing a 9P fileserver isn't easy, it requires far more than just implementing the 9P protocol. You also need to implement a file system, with all of the gotchas and edge cases that go with that.

To make matters even more difficult, testing a 9P server can be very frustrating as an error can mean that a mount in Plan 9 or Linux can hang the Operating System, requiring a long wait or a reboot.

1.1. How does Virgil work?

Virgil started out as a re-implementation of the excellent pjdfstestnfs test suite, which I found via the ZeroFS project. The main difference between pjdfstestnfs and Virgil is that Virgil tests 9P servers directly, rather than via a Linux mount. This makes it easier and faster to iterate on a server design.

I should note that while pjdfstestnfs served as the initial basis for Virgil, many of the tests were found via other methods including manual testing, mutation testing, fuzzing, differential fuzzing, and formal verification via Dafny.

1.2. How to use Virgil

The basics of using Virgil is to write a program that reads 9P messages via STDIN and 9P messages out via STDOUT.

Then you run Virgil by passing the name of your program via the command line. If the name of your program was example-server you'd call Virigil like this: 

./virgil stdio://./example-server

The example above uses the "stdio" protocol by default, because it's faster. But Virigil also supports "tcp" (TCP/IP) and "wss" (WebSockets) - I highly recommend using the "stdio" interface because it's much faster insomuch as it doesn't have to start your software up as a server and mantage the lifecycle.

Virgil will start running tests against your program, starting from roughly the easiest thing to do, then moving into harder and harder challenges.

The basic loop that you will be following is this:

  • Run Virgil
  • Read the error and hint for how to implement the next feature
  • Loop until all tests pass

Once all of the tests pass, then you'll be able to mount your filesystem in a real operating system like Linux or Plan 9.

1.3. High level guidance for writing an 9P server

After spending a lot of time working on Virgil, here are the high level things to keep in mind as you implement a 9P server:

  1. Do all of the 9P message encoding and decoding in one place. You may be tempted to spread some of the decoding work into various functions. Don't do this! Implement all encoding and decoding in a single function or object.
  2. Implement your filesytem as a tree. Even if you're only going to be serving a few files, you will want to use a whole dang tree structure. Trust me on this one.
  3. Use a single custom error function to send errors. Linux expects very specific error strings. But Virgil requires verbose error messages to make sure you're doing the right thing. This will make sense later.

1.4. Why is it called "Virigl"?

The successor to Plan 9 was called "Inferno" after the first cantica in Dante's "Divine Comedy". The 9P protocol we use today is technically called 9P2000 in the Plan 9 Operating System, or "Styx" in the Inferno Operating System. 9P2000 and Styx are the same protocol.

In Dante's Divine Comedy, the poet Virgil guides Dante through Hell, Pugatory, and Paradise.

1.5. How to test your 9P fileserver

Once you have a file server that passes all of the tests in Virgil, here is how you can test it!

If your code doesn't nativly support TCP/IP, you can use the socat command to serve it for you: 

socat TCP-LISTEN:4755,reuseaddr,fork EXEC:"example-server"

1.5.1. Linux

If you don't have a mount point for your 9P server, make one: 

mkdir /mnt/my9p

Then, run the command below, replacing 10.0.2.2 with the IP address for your 9P server. I use 10.0.2.2 because that's what my version of QEMU uses to route out of the VM to my local machine. 

mount -t 9p -o trans=tcp,port=4755,version=9p2000,uname=nobody,aname=/,cache=none,msize=65536 10.0.2.2 /mnt/my9p

Check out your new 9P server! 

ls -al /mnt/my9p

1.5.2. Plan 9

Assuming that your version of Plan 9 is on the same machine as your 9P server, then run this command inside of Plan 9: 

srv tcp!localhost!4755 my9p
mount -n /srv/my9p /n/my9p

Once it is mounted, then you can check it out using ls: 

ls -l /n/my9p
