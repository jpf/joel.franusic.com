Virgil

Virgil is a tool that guides you, step-by-step, through creating a fully functional 9P file server.

Writing a 9P fileserver isn't easy, it requires far more than just implementing the 9P protocol. You also need to implement a file system, with all of the gotchas and edge cases that go with that.

To make matters even more difficult, testing a 9P server can be very frustrating as an error can mean that a mount in Plan 9 or Linux can hang the Operating System, requiring a long wait or a reboot.

How does Virgil work?

Virgil started out as a re-implementation of the excellent pjdfstest_nfs test suite, which I found via the ZeroFS project. The main difference between pjdfstest_nfs and Virgil is that Virgil tests 9P servers directly, rather than via a Linux mount. This makes it easier and faster to iterate on a server design.

I should note that while pjdfstest_nfs served as the initial basis for Virgil, many of the tests were found via other methods including manual testing, mutation testing, fuzzing, differential fuzzing, and formal verification via Dafny.

How to use Virgil

The basics of using Virgil is to write a program that reads 9P messages via STDIN and 9P messages out via STDOUT.

For example, here is a basic program in Python that passes just the first test in Virgil: 

import struct
import sys

TVERSION = 100
RVERSION = 101

while True:
    header = sys.stdin.buffer.read(7)
    if len(header) < 7:
        break
    size, msg_type, tag = struct.unpack("<IBH", header)
    body = sys.stdin.buffer.read(size - 7)

    if msg_type == TVERSION:
        msize = struct.unpack("<I", body[0:4])[0]
        version = b"9P2000"
        sys.stdout.buffer.write(
            struct.pack("<IBHI H", 13 + len(version), RVERSION, tag, msize, len(version)) + version
        )

        sys.stdout.buffer.flush()

You would need to make the program executable: 

chmod +x example.py

And then, assuming that Virgil was in the same directory as example.py, you'd run it like this: 

./virgil stdio://./example.py

And then you'd see output like this:

Because the 9P protocol can be run over any bidirectional link which delivers messages in-order, you can run 9P over transports like serial links, named pipes, STDIN/STDOUT, TCP/IP, or WebSockets.

Right now, Virgil supports STDIN/STDOUT ("stdio"), TCP/IP ("tcp"), and WebSockets ("wss")

I highly recommend using the "stdio" interface for development because it will give you the fastest feedback on the status of your 9P implementation.

The way that Virgil works is that it runs a whole suite of tests against your program, starting from roughly the easiest, then moving onto harder and harder challenges.

The basic loop that you will be following is this:

  • Run Virgil
  • Read the error and hint
  • Write some code
  • Repeat until all tests pass

Once all of the tests pass, then you'll be able to mount your filesystem in a real operating system like Linux or Plan 9.

I use a Python example above, but here are two other programs that pass just the first test in Virgil:

Here is one in JavaScript: 

const TVERSION = 100;
const RVERSION = 101;

let buf = Buffer.alloc(0);
process.stdin.on("data", (chunk) => {
  buf = Buffer.concat([buf, chunk]);
  while (buf.length >= 7 && buf.length >= buf.readUInt32LE(0)) {
    const msg = buf.subarray(0, buf.readUInt32LE(0));
    buf = buf.subarray(msg.length);

    if (msg[4] === TVERSION) {
      process.stdout.write(Buffer.concat([
        Buffer.from([19, 0, 0, 0, RVERSION]),
        msg.subarray(5, 11),
        Buffer.from("\x06\x009P2000", "latin1"),
      ]));
    }
  }
});

Like the Python example, make it executable with chmod +x example.js and run it with: 

./virgil stdio://./example.js

and here is one in Go: 

package main

import (
        "encoding/binary"
        "io"
        "os"
)

const Tversion, Rversion = 100, 101

func main() {
        for {
                header := make([]byte, 7)
                if _, err := io.ReadFull(os.Stdin, header); err != nil {
                        return
                }
                body := make([]byte, binary.LittleEndian.Uint32(header[:4])-7)
                if _, err := io.ReadFull(os.Stdin, body); err != nil {
                        return
                }

                if header[4] == Tversion {
                        reply := []byte{19, 0, 0, 0, Rversion}
                        reply = append(reply, header[5:7]...)
                        reply = append(reply, body[:4]...)
                        reply = append(reply, "\x06\x009P2000"...)
                        os.Stdout.Write(reply)
                }
        }
}

Go programs need to be compiled before Virgil can run them: 

go build -o example-go example.go
./virgil stdio://./example-go

High level guidance for writing an 9P server

After spending a lot of time working on Virgil, here are the high level things to keep in mind as you implement a 9P server:

  1. Do all of the 9P message encoding and decoding in one place. You may be tempted to spread some of the decoding work into various functions. Don't do this! Implement all encoding and decoding in a single function or object.
  2. Implement your filesystem as a tree. Even if you're only going to be serving a few files, you will want to use a whole dang tree structure. Trust me on this one.
  3. Use a single custom error function to send errors. Linux expects very specific error strings. But Virgil requires verbose error messages to make sure you're doing the right thing. This will make sense later.

Why is it called "Virgil"?

The successor to Plan 9 was called "Inferno" after the first cantica in Dante's "Divine Comedy". The 9P protocol we use today is technically called 9P2000 in the Plan 9 Operating System, or "Styx" in the Inferno Operating System. 9P2000 and Styx are the same protocol.

In Dante's Divine Comedy, the poet Virgil guides Dante through Hell, Purgatory, and Paradise.

How to test your 9P fileserver

Once you have a file server that passes all of the tests in Virgil, here is how you can test it!

If your code doesn't natively support TCP/IP, you can use the socat command to serve it for you: 

socat TCP-LISTEN:4755,reuseaddr,fork EXEC:"example-server"

Linux

If you don't have a mount point for your 9P server, make one: 

mkdir /mnt/my9p

Then, run the command below, replacing 10.0.2.2 with the IP address for your 9P server. I use 10.0.2.2 because that's what my version of QEMU uses to route out of the VM to my local machine. 

mount -t 9p -o trans=tcp,port=4755,version=9p2000,uname=nobody,aname=/,cache=none,msize=65536 10.0.2.2 /mnt/my9p

Check out your new 9P server! 

ls -al /mnt/my9p

Plan 9

Assuming that your version of Plan 9 is on the same machine as your 9P server, then run this command inside of Plan 9: 

srv tcp!localhost!4755 my9p
mount -n /srv/my9p /n/my9p

Once it is mounted, then you can check it out using ls: 

ls -l /n/my9p
